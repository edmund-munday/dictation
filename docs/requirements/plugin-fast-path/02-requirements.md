# Requirements
- R236 Local fast path. With the gateway backend and >=1 enabled plugin, on release the transcript is normalised (lowercase, punctuation stripped, leading fillers such as "um", "uh", "so", "okay" removed) and matched against enabled plugins' trigger templates (exact, or prefix + trailing {arg}). On a single unambiguous match the command is queued straight away and NO gateway request is made. Pass: "Um, take a screenshot." with gateway backend makes zero gateway requests and produces a command request for screenshot (args filled from {arg}, e.g. "take a screenshot of the error dialog" -> subject "the error dialog"). Fail: a gateway request is sent, or the text is typed.
  - No match ("I need to take a screenshot later"), a missing required arg, or a tie between two plugins on equally specific templates: the gateway is called as before.
  - Secure fields: never runs a command, nothing typed by the fast path.
- R237 Per-plugin cancel window. Optional plugin JSON field `confirm_delay_s` (seconds, default 1.5, clamped 0...10). A command waits that long with "Running: <plugin>" before being run; any key cancels within the window. With 0 the command request appears immediately on release (no clock advance) when matched by the fast path. Pass: plugin without the field still waits 1.5 s; plugin with 0 runs with no delay; plugin with 0.5 runs after 0.5 s and not before.
  - Bundled defaults: the shipped echo and screenshot plugins declare confirm_delay_s 0.
