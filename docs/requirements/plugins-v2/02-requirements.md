# Requirements (app changes; plugin scripts live in the plugins folder and bundled defaults)
- R244 Plugin stdout `{"replace": "..."}` (PluginOutput.replace): the text replaces the current selection in the field targeted by the command, through the normal insertion path (InsertRequest with replacesSelection true, never auto-sent). If both replace and insert are given, replace wins. Empty replace does nothing.
- R245 Plugin JSON `"needs_selection": true` (PluginSpec.needsSelection, default false): if the focused field at release has no selection, the command is not run and the panel shows "Select some text first." Nothing is typed.
- R246 The selected text at release travels with the command: `CommandRequest.selectedText` (from FocusSnapshot.selectedText, a new optional field; nil for secure fields / no selection). The Mac runner passes it as env DICTATION_SELECTED_TEXT and as context.selected_text on stdin. AccessibilityBridge reads kAXSelectedTextAttribute when a non-secure selection exists.
- R247 Plugin JSON `"manages_media": true` (PluginSpec.managesMedia, default false). MediaPauseCoordinator gains `handOff() -> Bool`: returns whether the dictation had paused media and forgets it (no resume afterwards). When a manages_media command is queued from the utterance, the app does not resume media at dictation end; it calls handOff() before running the plugin and passes DICTATION_MEDIA_WAS_PLAYING=1|0 (context.media_was_playing). So 'pause' leaves media paused, 'play' resumes exactly once, 'next track' skips and keeps playing state.
- R248 HoldPipeline fires onCaptureEnd after the release has reached the session (so a fast-path command is already in session.commandRequests when the callback runs); cancel by another key still fires it once.
